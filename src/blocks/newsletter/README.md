# BW Newsletter Signup

## Description

A provider-agnostic email signup form. The form submits directly to the
endpoint supplied by your newsletter service, so no subscription data is stored
by BlockWriter.

## Features

- Optional heading, description, and consent text.
- Email field with a configurable field name for provider compatibility.
- Optional name field.
- Configurable form endpoint and submit method.
- Accessible, labelled inputs and a native submit button.

## Attributes

- `heading` (string) — Form heading.
- `description` (string) — Supporting copy.
- `placeholder` (string) — Email input placeholder.
- `buttonText` (string) — Submit button label.
- `showName` (boolean) — Include an optional name field.
- `namePlaceholder` (string) — Name input placeholder.
- `actionUrl` (string) — Provider form endpoint.
- `method` (string) — `post` or `get`.
- `emailField` (string) — `name` attribute for the email input.
- `nameField` (string) — `name` attribute for the name input.
- `consentText` (string) — Optional small print.
- `htmlId` (string) — Optional wrapper ID.
- `extraClass` (string) — Optional extra wrapper class.

## Usage

1. Insert the **BW Newsletter Signup** block.
2. Open the block settings and paste the form **Action URL** from your
   newsletter provider (Mailchimp, Brevo, MailerLite, and similar services
   expose an embed form endpoint).
3. Match the **Email field name** to the name your provider expects, for
   example `EMAIL`.
4. Publish and submit a test signup.

The form markup is generated by `src/blocks/newsletter/render.php`. Field names
are restricted to letters, numbers, `_`, `-`, and `[]`.

## Accessibility

Inputs are associated with labels, the email field uses `type="email"` and is
required, and the submit control is a native button. Screen-reader-only labels
are used when a visible label is not desired.

## Browser Support

Modern evergreen browsers.
